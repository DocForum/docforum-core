- [x] Coverage reporting with per-module floors in CI. Tracked as [issue #346](https://github.com/DocForum/docforum-core/issues/346) — **Done:** `npm run test:coverage` in `backend/` runs the unit and integration suites in one vitest process with the v8 provider, so a single report is the union of both rather than two separately-collected ones, and `vitest.config.mts` pins statements/functions/branches/lines floors for the five correctness-critical modules (appointments, availability, referrals, orders, payments) at the levels measured when the gate landed, less a fixed amount of runner slack. The `Backend` job runs the step and uploads `backend/coverage/` (html, `lcov.info`, `coverage-summary.json`) as the `coverage-report` artifact. Every other directory stays ungated so an unrelated PR cannot fail on someone else's coverage. No schema, endpoint or production-dependency changes; the coverage gaps the report exposes are recorded for their own issues.
- [x] Docs site built on pull requests. Tracked as [issue #347](https://github.com/DocForum/docforum-core/issues/347) — **Done:** `.github/workflows/build-docs.yml` runs the same `GITHUB_PAGES=true npm run build` that `deploy-docs.yml` runs on `main`, path-limited to the site's own files and the documents it copies in, so a broken docs change reddens the PR instead of the deploy. Build only — no Pages artifact upload and no deploy — under `permissions: contents: read` with `persist-credentials: false`, so a fork PR gets a read-only token and no publish path. `ignoreDeadLinks` is explicitly `false` in `docs/site/.vitepress/config.ts`, which makes that same build the PR-time dead-link gate.
